# Security Architect Mentorship Program

A structured, 16-phase curriculum that transforms a strong software engineer into a security architect with hands-on, attacker-first methodology — then extends into data engineering, business architecture, AI security, and LLM systems.



## Curriculum — 16 Phases

| Phase | Name | Sessions | Core Question | What You Walk Away With |
|-------|------|----------|---------------|------------------------|
| 01 | Linux Deep Internals | 12 | How does the OS control what processes can do — and how does that break? | You can read /proc, trace syscalls, understand namespaces, cgroups, capabilities. You stop treating the OS as a black box. |
| 02 | Networking & Protocols | 10 | What moves on the wire — and where can it be intercepted, forged, or broken? | You can read packet captures, understand TLS handshakes, identify spoofing and MITM at the protocol level. |
| 03 | Software Architecture Fundamentals | 10 | How do you design systems that are scalable, observable, and evolvable? | CAP theorem, CQRS, event sourcing, saga pattern, API design, observability (SLOs, burn rates), DDD, capacity planning. |
| 04 | Cloud Fundamentals | 10 | What are the shared primitives across AWS, Azure, and GCP — and who owns what failure mode? | VPC design, shared responsibility, IAM patterns, compute models, storage, FinOps, migration strategy — vendor-neutral. |
| 05 | Azure Security Posture | 10 | Beyond deploying — who can do what, from where, and how would you know? | Azure-specific: Defender, Sentinel, PIM, Conditional Access, landing zones, security center. |
| 06 | Cloud-Native Security | 8 | How do containers, service meshes, and observability change the security model? | Container security, Kubernetes RBAC, service mesh, supply chain (SBOM, signing), runtime threat detection. |
| 07 | Data Engineering & Platform | 10 | How do you build and secure streaming pipelines, data lakes, and ML platforms at scale? | Kafka, data lakes (Bronze/Silver/Gold), Spark, Flink, MLOps, data governance, GDPR lineage, quality contracts, FinOps for data. |
| 08 | Distributed Systems Security | 8 | How do failure modes and scale create security problems single-system thinking misses? | Failure modes at scale, consensus, clock drift, idempotency, secrets management, lateral movement in distributed systems. |
| 09 | Architecture Frameworks | 8 | How do you document decisions so security trade-offs are explicit and auditable? | C4 diagrams, ADRs, arc42, threat modeling as a design activity, documentation that survives team turnover. |
| 10 | Security Mindset & Threat Modeling | 12 | How does an attacker think — and how do you build that into your design process? | STRIDE, attack trees, PASTA, security requirements from first principles, attacker-first design reviews. |
| 11 | Secure Coding | 10 | What does vulnerable code look like in Node.js and C# — and how do you fix it at the pattern level? | OWASP Top 10 in Node.js and C# — at the pattern level, not the checklist level. |
| 12 | Security Architecture Frameworks | 10 | How do you design security in from the beginning — not bolt it on at the end? | Zero Trust, defense in depth, SABSA, security patterns, designing security into systems from the start. |
| 13 | Compliance & Governance | 8 | How do regulatory requirements map to technical controls — and how do you make it auditable? | SOC 2, ISO 27001, GDPR, PCI DSS mapped to actual technical controls with evidence packs. |
| 14 | Business Architecture | 8 | How do organizational structure, capability maps, and technology decisions interact? | Capability mapping, Conway's Law, team topologies, build vs buy, tech debt as financial risk, stakeholder communication, digital transformation. |
| 15 | AI Security Architecture | 12 | How do AI systems change the threat model — and how do you architect security for systems where the "code" is a model you don't fully control? | Prompt injection, model inversion, RLHF poisoning, supply chain for ML, EU AI Act, securing LLM-powered systems. |
| 16 | AI Engineering & LLM Systems | 12 | How do LLMs actually work under the hood — and how do you build production systems on top of them? | Transformers, pre-training, RAG pipelines, agents, tool use, reasoning models, production LLM systems. |

**Total: 158 sessions**

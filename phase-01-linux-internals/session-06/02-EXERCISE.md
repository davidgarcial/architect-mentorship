## The Artifact
A Kubernetes Deployment YAML for a production API service with two containers — the API itself and a Redis sidecar. Neither container has a `resources` block. This is not a contrived example; it is the default state of most YAML generated by `kubectl create deployment` and scaffold tools. The absence of limits has security implications beyond "it might use too much memory."

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-service
spec:
  replicas: 3
  selector:
    matchLabels:
      app: api-service
  template:
    metadata:
      labels:
        app: api-service
    spec:
      containers:
      - name: api
        image: myapp:latest
        ports:
        - containerPort: 8080
        # No resources block — no limits, no requests
      - name: redis
        image: redis:7
        ports:
        - containerPort: 6379
        # No resources block
```

Your task is to enumerate every security implication of the missing `resources` block — not just "it could OOM" — and write the corrected YAML with appropriate limits, requests, and a LimitRange to enforce minimums cluster-wide.

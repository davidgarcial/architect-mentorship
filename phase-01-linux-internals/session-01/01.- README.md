# Phase 01 — Linux Deep Internals | Session 01

## Session Goal
Build the habit of reading a system artifact and reasoning about it as an attacker — not as the engineer who wrote it.

## The Artifact
`Dockerfile` — a containerized Python application.

## Your Task (before reading anything else)

**Step 1 — Exploit chain first.**
Look at this Dockerfile line by line. For each problem you find, do not stop at naming it. Answer:
- What does an attacker do with this?
- What is the next step after that?
- Where does it end?

Write your analysis in `SOLUTION.md`. Use this structure for each finding:

```
## Finding N: [name]
**Line(s):** ...
**What it is:** ...
**Exploit chain:** step 1 → step 2 → step 3 → end state
**Impact:** ...
```

**Step 2 — Attack surface count.**
How many distinct ways can an attacker get initial access to this container?

**Step 3 — Worst-case scenario.**
If this container is running on a Kubernetes node alongside 5 other containers — what is the worst realistic end state for an attacker who gets in?

## Acceptance Criteria

FUNCTIONAL
- [ ] Container builds and the app runs

SECURITY
- [ ] You identify all planted issues (there are at least 6)
- [ ] Each finding includes a full exploit chain, not just a label
- [ ] Worst-case scenario is written from attacker perspective, not defender perspective

OBSERVABLE
- [ ] Your SOLUTION.md shows your reasoning, not just conclusions
- [ ] Someone reading it could reproduce your exploit chain thinking

STRETCH
- [ ] Rewrite the Dockerfile to fix all issues
- [ ] Demonstrate that `docker run` with your hardened version fails to do something the original allowed

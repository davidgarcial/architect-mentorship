## Diff — Broken vs Hardened

```diff
- FROM ubuntu:22.04
+ FROM python:3.12-slim
# ubuntu:22.04 ships ~400 packages. python:3.12-slim ships ~80.
# Everything removed is attack surface that disappears.
# In production, pin the digest:
#   FROM python:3.12-slim@sha256:<digest>

- RUN apt-get update && apt-get install -y \
-     curl \
-     wget \
-     netcat \
-     python3 \
-     python3-pip \
-     sudo \
-     openssh-server \
-     && rm -rf /var/lib/apt/lists/*
+ RUN apt-get update && apt-get install -y --no-install-recommends \
+     python3-pip \
+     && apt-get clean && rm -rf /var/lib/apt/lists/*
# Removed: curl, wget, netcat → reverse shell and download tools
# Removed: sudo → privilege escalation path
# Removed: openssh-server → SSH daemon has no place in an app container
# python3 already included in the base image
# --no-install-recommends prevents pulling optional packages

- RUN useradd -m -s /bin/bash appuser && \
-     echo "appuser ALL=(ALL) NOPASSWD:ALL" >> /etc/sudoers
+ RUN useradd --uid 1001 --no-create-home --shell /usr/sbin/nologin appuser
# Removed: NOPASSWD:ALL sudo → was identical to running as root
# --no-create-home: no writable home directory for the user
# --shell /usr/sbin/nologin: interactive shell blocked even if credentials leak

  COPY app/ /app/

- RUN chmod -R 777 /app
+ RUN chown -R appuser:appuser /app && chmod -R 550 /app
# 777: any user, any process can overwrite app code → backdoor persistence path
# 550: owner+group can read+execute, others: nothing
# appuser owns the files, so the app can read them without needing write access

- # Set up SSH
- RUN mkdir /var/run/sshd && \
-     echo 'root:password123' | chpasswd && \
-     sed -i 's/#PermitRootLogin prohibit-password/PermitRootLogin yes/' /etc/ssh/sshd_config && \
-     sed -i 's/#PasswordAuthentication yes/PasswordAuthentication yes/' /etc/ssh/sshd_config
# Removed entirely.
# Hardcoded password visible in: docker history, git log, any registry push.
# SSH in a container = persistent network attack surface serving no app function.
# Debug containers with: kubectl exec -it <pod> -- sh
# Or use an ephemeral debug container: kubectl debug -it <pod> --image=busybox

- RUN pip3 install -r /app/requirements.txt
+ RUN pip3 install --no-cache-dir --require-hashes -r /app/requirements.txt
# --require-hashes: every package must match a sha256 in requirements.txt
# Any tampered package → build fails immediately (not silently installs)
# --no-cache-dir: pip download cache not stored in the image layer

  WORKDIR /app

  EXPOSE 8080
- EXPOSE 22
# Removed: no SSH daemon, no port 22

- # Run as root for "simplicity"
- USER root
+ USER appuser
# Process runs as UID 1001. RCE gives attacker an unprivileged shell.
# Container escape from non-root requires a separate privilege escalation step.

- CMD ["/bin/bash", "-c", "/usr/sbin/sshd && python3 app.py"]
+ CMD ["python3", "app.py"]
# Removed: sshd from CMD
# PID 1 IS the application. When app crashes → container exits → K8s restarts it.
# Bash wrapper as PID 1 means app crash doesn't exit the container → invisible failure.
```

## Hardened Dockerfile

```dockerfile
FROM python:3.12-slim

# Install only what the app needs at runtime
RUN apt-get update && apt-get install -y --no-install-recommends \
    python3-pip \
    && apt-get clean && rm -rf /var/lib/apt/lists/*

# Non-root user: no home, no login shell, no sudo
RUN useradd --uid 1001 --no-create-home --shell /usr/sbin/nologin appuser

WORKDIR /app

# Dependencies first — this layer caches independently from app code
COPY app/requirements.txt .
RUN pip3 install --no-cache-dir --require-hashes -r requirements.txt

# Application code only — no .env, no secrets, no dev files
COPY app/ .

# appuser owns the files; no world access
RUN chown -R appuser:appuser /app && chmod -R 550 /app

# Drop to non-root before the process starts
USER appuser

EXPOSE 8080

CMD ["python3", "app.py"]
```

## Evidence — Verify Each Fix

Run these commands against both images to confirm the changes are effective.

```bash
# Build both
docker build -t app-broken -f Dockerfile.broken .
docker build -t app-hardened -f Dockerfile .

# ── Fix 1: USER root → USER appuser ──────────────────────────────────────────
docker run --rm app-broken  id
# Expected: uid=0(root) gid=0(root) groups=0(root)

docker run --rm app-hardened id
# Expected: uid=1001(appuser) gid=1001(appuser) groups=1001(appuser)

# ── Fix 2: sudo removed ───────────────────────────────────────────────────────
docker run --rm app-broken  sudo id
# Expected: uid=0(root) — escalation succeeds

docker run --rm app-hardened sudo id
# Expected: bash: sudo: command not found

# ── Fix 3: netcat/wget/curl removed ──────────────────────────────────────────
docker run --rm app-broken  sh -c "which nc wget curl"
# Expected: /usr/bin/nc  /usr/bin/wget  /usr/bin/curl

docker run --rm app-hardened sh -c "which nc wget curl"
# Expected: (empty — none found)

# ── Fix 4: chmod 777 → 550 ───────────────────────────────────────────────────
docker run --rm app-broken  ls -la /app/app.py
# Expected: -rwxrwxrwx (777)

docker run --rm app-hardened ls -la /app/app.py
# Expected: -r-xr-x--- (550)

# Attempt to overwrite app code as a different user
docker run --rm --user 1002 app-broken  sh -c "echo pwned >> /app/app.py && echo WRITTEN"
# Expected: WRITTEN  (attack succeeds)

docker run --rm --user 1002 app-hardened sh -c "echo pwned >> /app/app.py && echo WRITTEN"
# Expected: sh: can't create /app/app.py: Permission denied

# ── Fix 5: SSH removed ────────────────────────────────────────────────────────
docker run --rm app-broken  sh -c "ss -tlnp 2>/dev/null | grep :22 && echo SSH_RUNNING"
# Expected: SSH_RUNNING

docker run --rm app-hardened sh -c "ss -tlnp 2>/dev/null | grep :22 && echo SSH_RUNNING"
# Expected: (empty — SSH not running)

# ── Fix 6: hardcoded password not in history ──────────────────────────────────
docker history app-broken --no-trunc | grep password
# Expected: echo 'root:password123' | chpasswd  (visible in plain text)

docker history app-hardened --no-trunc | grep password
# Expected: (empty)

# ── Attack surface comparison ─────────────────────────────────────────────────
docker run --rm app-broken  dpkg -l | wc -l
docker run --rm app-hardened dpkg -l 2>/dev/null | wc -l
# hardened should have significantly fewer installed packages
```
